    1.1. Ionic 在客户端/服务器应用中的角色

    应用由两部分组成，它们之间只通过 HTTP 请求进行通信：

    • 1：运行在手机上的 [Ionic] 应用向服务器发送 HTTP 请求，例如 [GET /api/schedule?doctorId=1&day=2026-10-05]；
    • 2：服务器以 JSON 数据作为响应：即该医生当天的日程。它不生成任何页面；
    • 3：利用这些数据，[Angular] 更新手机屏幕。

    这正是 [Flutter]、[React]、[Vue.js] 和 [Angular] 客户端的架构：唯一的区别在于由谁来生成显示。在这一点上，[Ionic] 与 [Flutter] 恰好相反。[Flutter] 是一个渲染引擎：它完全不依赖浏览器，自己渲染屏幕上的每一个像素。[Ionic] 则相反，它本身不渲染任何内容：它是一个 Web 组件库：即新的 HTML 元素——[<ion-button>]、[<ion-input>]、[<ion-list>]、[<ion-tabs>]……，它们由 [Stencil] 工具（来自 [Ionic] 团队）创建，任何浏览器都能显示。这些组件以两种“模式”模仿手机的原生组件：[md] （[Material Design]，即 [Android] 的外观）和 [ios] （[iPhone] 的外观）。本课程在所有地方（包括浏览器中）都强制使用 [md] 模式。由于它们只是普通的 HTML 元素，[Ionic] 的组件可以与 [Angular]、[React] 或 [Vue.js] 一起使用：本课程将它们与 [Angular] （即 [@ionic/angular] 包）搭配使用。

    因此，应用是一个标准的 Web应用：一个 HTML 页面、一个样式表，以及由 [JavaScript] 代码，它们是从 [TypeScript] 编译而来的。将它变成 [Android] 应用的是 [Capacitor] （与 [Ionic] 来自同一团队）：

    • [Capacitor] 会生成一个原生的 [Android] 项目，其唯一的屏幕是一个 WebView：即手机上 [Chrome] 浏览器引擎，全屏显示，没有地址栏。编译后的 Web 应用被复制到这个项目中，WebView 在启动时加载它。对用户来说，它与任何其他应用无异：有图标、启动画面，以及 [Android] 的返回按钮；
    • [JavaScript] 代码通过 [Capacitor] 插件访问手机的功能（存储、相机、通知、地理定位等），这些插件充当通往原生代码的桥梁。本课程使用其中两个：[@capacitor/preferences]（设备上的一个小型键值存储，见示例 20）和 [CapacitorHttp] （由 [Android] 的原生代码发出的 HTTP 请求，见示例 22 至 25）；
    • 同样的代码在浏览器中运行，插件在浏览器中有 Web 版本（此时 [Capacitor] 的存储使用浏览器的 [localStorage]）。因此我们在 [Chrome] 中以手机尺寸、借助其开发者工具进行开发，然后再切换到 [Android] 上进行测试。

    应用的三个层次，以及它们各自提供的功能：

    • [Angular]：应用框架。它提供组件（一个 [TypeScript] 类和一个 HTML 模板）、信号（即状态，其变化会更新屏幕）、依赖注入（服务、共享状态）、路由器（每个屏幕一个地址）、表单、HTTP 客户端，以及“管道”（格式化）。[Flutter] 课程的读者会认出这一原则：界面是状态的函数。我们从不直接修改屏幕本身：我们修改状态，由 [Angular] 更新所有依赖于该状态的内容；
    • [Ionic]：界面组件，它们类似于移动应用的组件（工具栏、列表、字段、悬浮按钮、选项卡、警告窗口、日历等），以及移动应用的导航：一个页面栈，带有如同 [Android] 中的动画，返回按钮会将页面从栈中弹出；
    • [Capacitor]：[Android] 应用以及对手机的访问。

    与 [Flutter] 不同，与服务器通信不需要额外的包：[Angular] 提供了 HTTP 客户端、路由器、表单和依赖注入；[JavaScript] 连同 [Intl] 对象，为每种语言提供日期和数字格式化；随 [RxJS] 库一起包含在 [Angular] 中，提供异步数据流。翻译（示例 21）由一个专门为此编写的小类处理，它读取 JSON 字典。

    1.2. 所用工具

    这些示例是使用以下工具编写和测试的（它们的安装见下一章和附录）：

    • [Node.js] 24 及其包管理器 [npm]：[Angular CLI] 22 要求 [Node.js] 22.22.3（或更新的 22 版本）、24.15 或更高版本，或 26 及以上版本。[Node.js] 还负责运行 JSON 服务器；
    • [Angular CLI] 22.2（[ng] 命令）、[Angular] 22.2 和 [TypeScript] 6.0；
    • [Ionic] 9.0（[@ionic/angular] 9.0.6 包）及其图标 [ionicons] 8.1；
    • [Capacitor] 8.5（包 [@capacitor/core]、[@capacitor/android] 和 [@capacitor/cli]）及其插件 [@capacitor/preferences] 8.0；
    • [Visual Studio Code] 编辑器及其扩展 [Angular Language Service] 和 [Ionic]；
    • [Android Studio]，用于获取 [Android] SDK、其 JDK 以及模拟器管理器：[Android] 模拟器 （电脑上的模拟手机），或连接到电脑的真实 [Android] 手机；
    • [Chrome] 浏览器，用于在电脑和手机上开发和调试应用；
    • [MySQL] 数据库管理系统 （或 [MariaDB]），例如 [Laragon] 在 [Windows] 下提供的那个：JSON 服务器需要它，详见介绍服务器的那一章；
    • 命令行工具 [curl]，用于显示原始的 HTTP 响应。

    所用的包来自两个 [package.json] 文件，它们所属的两个 [Ionic] 项目是相同的：[@angular/...] 22.2、[@ionic/angular] 9.0、[ionicons] 8.1、[@capacitor/...] 8.5、[@capacitor/app] 8.1、[@capacitor/preferences] 8.0、[rxjs] 7.8，以及仅用于开发的 [typescript] 6.0、[prettier] 3（代码排版）和 [playwright] 1.56（截图）。

    1.3. 截图

    本文档中的截图是由使用 [Playwright] 库的程序自动生成的（来自两个 [captures/] 文件夹，它们属于两个 [Ionic] 项目）。[captures/captures.mjs] 程序控制一个 [Chromium] 浏览器（[Chrome] 的免费版本），其大小为 [Android] 手机的尺寸：412 x 892 点，每点 2.625 像素，得到 1082 x 2342 像素的图像。对于每个示例，它会运行 [captures/scenarios/] 文件夹中的一个“场景”：打开示例页面，像用户一样与之交互（输入文本、按下按钮），然后将屏幕保存为图像文件。

    因此这些是应用的真实截图，由 [Chrome] 引擎渲染——与手机 WebView 所用的正是同一个引擎；缺少的只有手机的状态栏（时间、电量）和屏幕键盘。读者可以自行重新生成它们（应用必须处于运行状态；见下文）：

    1
2
3
    npx playwright install chromium
npm run captures
node captures/captures.mjs 05 17
    • 第 1 行：仅需执行一次：下载 [Chromium] 浏览器，供 [Playwright] 使用；
    • 第 2 行：重新生成 [captures/images/] 文件夹中的所有截图；
    • 第 3 行：仅重新生成示例 05 和 17 的截图。

    示例 22 至 25 和案例研究的截图还要求 JSON 服务器以验证码（CAPTCHA）的“测试模式”运行（见介绍服务器的那一章）。
