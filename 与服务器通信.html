    9. 与服务器通信

    现在必须启动 JSON [RdvMedecins] 服务器（端口 8080），如上一章所述，最好使用验证码测试模式（[CAPTCHA_TEST=test]），这样你可以对任何图片都回答“test”。

    示例 22 至 25 共用几个文件，位于项目的 [src/app/common/] 文件夹中：服务器地址（[config.ts]）、响应类型（[types.ts]）、错误类（[api-error.ts]）、请求服务（[api.ts]）和登录栏（[login-bar.ts]）。它们会在各个示例中随着相关性的出现而逐步介绍。

    // =========================================================================
// src/app/common/config.ts - JSON 服务器在哪里（WHERE）？
// -------------------------------------------------------------------------
// 对于由服务器自己提供服务的 Web 应用，这个问题并不存在：
// 请求发往与页面相同（SAME）的源
// （相对地址，/api/...）。但移动（MOBILE）应用没有
// 可用的源（在 Android 上，页面由 Capacitor 从
// https://localhost 提供）：必须给它服务器的完整地址。
//   - 在 Web 开发（ng serve）中，Angular 的开发
//     服务器会把 /api 请求转发给 JSON 服务器（文件
//     proxy.conf.json）：使用相对地址就够了；
//   - Android 模拟器通过
//     地址 10.0.2.2 看到运行它的电脑（对它来说 localhost 是模拟器自身）；
//   - 连接到与电脑相同 Wi-Fi 网络的真实手机必须
//     使用电脑在该网络上的地址（192.168.1.20……）：
//     在构建应用程序时提供：
//         ng build --define "SERVER='http://192.168.1.20:8080'"
//     或者修改下面的 androidServer 常量。
// =========================================================================

import { Capacitor } from '@capacitor/core';

// Android 应用程序的服务器地址，在没有强制指定其他地址时使用：
// 从模拟器看到的电脑地址
const androidServer = 'http://10.0.2.2:8080';

// 构建时由 --define "SERVER='...'" 给出的值
// （ng build、ng serve）。该选项会在编译后的代码中把单词
// SERVER 替换为给定的值。没有它，SERVER 就不存在：typeof
// 让我们可以在不引发错误的情况下检查它
declare const SERVER: string | undefined;
const forcedServer = typeof SERVER === 'string' ? SERVER : '';

export const config = {
  // Capacitor.isNativePlatform()：在 Android（或 iOS）应用中为 true，
  // 在浏览器中为 false；Capacitor.getPlatform()：'android'、'ios' 或 'web'
  serverUrl:
    forcedServer !== ''
      ? forcedServer
      : !Capacitor.isNativePlatform()
        ? '' // Web：同源，使用相对地址
        : Capacitor.getPlatform() === 'android'
          ? androidServer
          : 'http://localhost:8080',
};
    • 第 21 行：[Capacitor]，[@capacitor/core] 中提供应用所运行平台信息的对象。它可以在任何地方使用，包括在浏览器中；
    • 第 25 行：默认地址是 [Android] 的。模拟器是一台拥有自己网络的独立机器：对模拟器而言，[localhost] 指的是模拟器自身。特殊地址 [10.0.2.2] 指的是运行它的电脑；
    • 第 31–32 行：在应用构建期间由 [--define] 选项（来自 [Angular]）强制指定的地址：[ng build --define "SERVER='http://192.168.1.20:8080'"]。编译时会把代码中的标识符 [SERVER] 替换为给定的值（一个字符串，因此带有单引号）。没有这个选项时，[SERVER] 并不存在：[declare const] 告知 [TypeScript] 编译器，[SERVER] 是一个它看不到其声明的标识符，而 [typeof SERVER] 使你可以在不引发错误的情况下测试它是否存在。这与 [--dart-define] 和 [String.fromEnvironment] 在 [Flutter] 中的做法完全对应；
    • 第 34–45 行：否则，使用特定于平台的地址。[Capacitor.isNativePlatform()] 在 [Android] （或 [iOS]）应用中为 true，但在浏览器中为 false；[Capacitor.getPlatform()] 返回 'android'、'ios' 或 'web'：
    • 在浏览器中（第 41 行）：相对 URL（''），也就是与应用相同的源；
    • 在 [Android] 中（第 43 行）：第 25 行的地址；
    • 其他情况（第 44 行，[iOS]，本课程不涉及）：[localhost]。

    连接到与服务器电脑相同 Wi-Fi 网络的真实手机，必须使用电脑在该网络上的地址（[ipconfig] 命令，来自 [Windows] ，可以提供它）：你可以在编译时通过 [--define] 传入它，或者修改第 25 行的常量。电脑的防火墙还必须允许 8080 端口上的传入连接。

// capacitor.config.ts - Capacitor 配置
// -------------------------------------------------------------------------
// Capacitor 将 Web 应用（ng build 生成的文件夹）
// 变成 Android 应用：它把 Web 应用包装在一个 Android Studio 项目中
// （android/ 文件夹），并由“WebView”显示，WebView 即
// 手机上 Chrome 浏览器的引擎。命令（见示例 01，“运行”）：
//     npx cap add android       （只需一次：创建 android/ 文件夹）
//     ng build                  （构建 Web 应用）
//     npx cap sync android      （将其复制到 Android 项目中）
//     npx cap run android       （在模拟器或手机上运行）
// =========================================================================

import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  // 应用在手机（以及 Play Store）上的唯一标识符
  appId: 'fr.stahe.examples',
  // 显示在图标下方的名称
  appName: 'Ionic Examples',
  // 已编译 Web 应用所在的文件夹（ng build）
  webDir: 'dist/examples_ionic/browser',
  server: {
    // 允许向开发用 JSON 服务器（示例 22 至 25）发送未加密的 HTTP 请求
    // （http://10.0.2.2:8080）
    cleartext: true,
  },
  plugins: {
    // CapacitorHttp：应用的 HTTP 请求不再由 WebView 发出，
    // 而是由 Android 的原生代码发出。后果（见
    // 示例 22 和 23）：没有 CORS 检查（JSON 服务器无需
    // 做任何放行配置），并且 Cookie（身份验证令牌所在的 Cookie）由
    // Android 存储并自动回传
    CapacitorHttp: {
      enabled: true,
    },
  },
};

export default config;
    • 第 23–27 行：[server.cleartext: true]。从 [Android] 9 版本起，应用程序只被允许使用 HTTPS 通信。我们的开发服务器使用 HTTP：我们予以允许。[npx cap sync android] 命令会把这项设置带到 [Android] 项目中（[android:usesCleartextTraffic="true"] 属性，添加到 [Capacitor] 与应用程序清单合并的清单中）。在生产环境中，服务器将使用 HTTPS，这项设置也就不再需要；
    • 第 28–37 行：[CapacitorHttp] 插件。应用程序的 HTTP 请求（[Angular] 的 HTTP 客户端发出的请求，以及 [fetch] 发出的请求）不再由 WebView 发送，而是由 [Android] 的原生代码发送。对于浏览器来说，应用程序（https://localhost）和服务器（http://10.0.2.2:8080）会被视为两个不同的源：浏览器会要求服务器提供 CORS 授权，而服务器并不授予，并且会拒绝带上令牌 Cookie。原生代码没有这些规则。然而，应用的 [TypeScript] 代码并不改变：重定向请求的是 [Capacitor] 。

    // =========================================================================
// src/app/ex22-http/ex22.page.ts - 向服务器发出的第一个 HTTP 请求
// -------------------------------------------------------------------------
// RdvMedecins JSON 服务器必须正在运行（端口 8080）。我们向它请求
// 一个验证码：GET /api/captcha -> { "id": "...", "svg": "<svg ...>" }。
//
//   - HttpClient：Angular 的 HTTP 客户端（由 main.ts 中的 provideHttpClient()
//     提供给整个应用程序）。http.get<T>(address) 返回
//     一个 Observable：当我们订阅（SUBSCRIBE）它（subscribe）时才会发出请求，
//     响应稍后到达，其 JSON 响应体已经被解码；
//   - 错误响应（4xx、5xx）或没有响应，会到达
//     订阅的 error 函数；
//   - 服务器的地址取决于应用程序运行的位置
//     （浏览器、Android 模拟器、手机）：见 common/config.ts；
//   - 需要显示三种状态：加载中、成功、出错；
//   - 验证码的图片是 SVG：<img> 标签可以显示它。
// =========================================================================

import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { Component, DestroyRef, inject, signal } from '@angular/core';
import {
  IonBackButton, IonButton, IonButtons, IonCard, IonCardContent, IonContent, IonHeader, IonNote, IonProgressBar,
  IonTitle, IonToolbar,
} from '@ionic/angular';
import { Subscription } from 'rxjs';
import { config } from '../common/config';
import { Captcha, captchaImage } from '../common/types';

@Component({
  selector: 'app-ex22',
  imports: [
    IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle, IonContent, IonProgressBar, IonCard, IonCardContent,
    IonButton, IonNote,
  ],
  templateUrl: './ex22.page.html',
  styles: `
    .error { --background: #ffebee; --color: #333; margin: 12px 0; }
    .image { border: 1px solid #ddd; border-radius: 6px; padding: 4px; text-align: center; }
    .image img { height: 60px; }
    .id { font-family: monospace; font-size: 11px; margin: 8px 0; }
  `,
})
export class Ex22Page {
  private readonly http = inject(HttpClient);
  readonly server = config.serverUrl || '(same origin: /api, ng serve proxy)';
  readonly captchaImage = captchaImage;

  // 屏幕的状态：信号
  readonly captcha = signal<Captcha | null>(null);
  readonly loading = signal(true);
  readonly error = signal<string | null>(null);
  readonly requestCount = signal(0);

  // 对正在进行的请求的订阅（如果有的话）
  private request?: Subscription;

  constructor() {
    this.load(); // 第一个请求，在页面一创建时就发出
    // 页面被销毁（返回按钮）：正在进行的请求被放弃
    inject(DestroyRef).onDestroy(() => this.request?.unsubscribe());
  }

  load(): void {
    // 取消订阅一个仍在进行中的请求会取消（CANCELS）它：它现在已无用的响应
    // 将永远不会被处理（不会有“过期”响应）
    this.request?.unsubscribe();
    this.loading.set(true);
    this.error.set(null);
    // <Captcha>：所期望的 JSON 响应体的类型（对
    // 编译器的一个承诺：运行时不会检查任何东西）
    this.request = this.http.get<Captcha>(`${config.serverUrl}/api/captcha`).subscribe({
      // next：响应已到达（代码 2xx），其 JSON 响应体已被解码
      next: (captcha) => {
        this.captcha.set(captcha);
        this.requestCount.update((n) => n + 1);
        this.loading.set(false);
      },
      // error：错误响应（4xx、5xx），或根本没有响应
      // （服务器已停止、地址错误：此时 status 为 0）
      error: (e: HttpErrorResponse) => {
        this.error.set(e.status === 0 ? 'no response (status 0)' : `the server responded ${e.status}`);
        this.captcha.set(null);
        this.loading.set(false);
      },
    });
  }
}

// 就在地址之中（IN）。由 <img> 显示的 SVG 图片无法运行

    9.2. 示例 23：登录、Cookie 和会话

    9.2.1. Cookie 是怎么回事？

    服务器把 JWT 令牌存放在 Cookie 中。此时，[Flutter] 客户端必须把它的 HTTP 客户端替换为另一个能读取每个响应中的 [Set-Cookie] 头、管理这些 Cookie（并将其保存在设备上），并在每个请求的 [Cookie] 头中把它们发回的客户端：[Flutter] 应用没有浏览器替它完成这些工作。

    而 [Ionic] 应用则无需编写任何代码：

    • 在电脑的浏览器中，是由浏览器保存 Cookie 并将其发回，就像对待任何其他网站一样。[ng serve] 代理使应用程序和 API 具有相同的源：[SameSite=Strict] Cookie 会被接受并发回。应用程序代码无法读取或写入这个 Cookie（[HttpOnly]）；
    • 对于 [Android]，[CapacitorHttp] 插件（示例 22）会让请求经过原生代码。[Capacitor] 在应用启动时，会把 [Android] 的 Cookie 管理器（WebView 使用的那个）设置为原生请求的管理器：收到的 Cookie 会保存在其中，并随后续发往同一服务器的请求发回。它们会保留在设备上（我们的 Cookie 的生命周期由 [Max-Age=7200]设定；只有没有过期时间的“会话”Cookie 才会在应用启动时被删除）：关闭并重新打开应用后，你仍保持登录状态。

    因此，令牌从不由应用程序的代码操作，也不会以明文形式保存在设备上（[Flutter] 客户端把它保存在 [shared_preferences] 中）。

// src/app/ex23-login/command.ts - 一个操作（ACTION）、它的状态、它的结果
// -------------------------------------------------------------------------
// 异步操作（登录、保存……）有一个状态，屏幕
// 必须显示出来：它是否正在运行（按钮被禁用）？它是否
// 以错误（消息）结束？这是架构指南（例如 Flutter 的指南）中的
// “Command”模式，精简到了最基本的部分：
//
//     readonly loginCommand = new Command();
//     this.loginCommand.execute(() => this.logIn());   // 启动该操作
//     loginCommand.running(), loginCommand.error()      // 它的状态
//
// 它的状态由信号（SIGNALS）构成：读取它们的模板会在
// 命令开始和结束时更新。
// =========================================================================

import { signal } from '@angular/core';

export class Command {
  private readonly _running = signal(false);
  private readonly _error = signal<unknown>(null);
  readonly running = this._running.asReadonly();
  readonly error = this._error.asReadonly();

  // 执行该操作，前提是没有另一个操作正在运行
  async execute(action: () => Promise<void>): Promise<void> {
    if (this._running()) return; // 不允许重复提交（双击按钮）
    this._running.set(true);
    this._error.set(null);
    try {
      await action();
    } catch (e) {
      this._error.set(e); // 错误会被保留（KEPT），以便显示
    } finally {
      // finally：在所有（ALL）情况下都会执行，无论成功还是出错
      this._running.set(false);
    }
  }

  clearError(): void {
    this._error.set(null);
  }
}

    • 第 19–23 行：一个简单的类（每个屏幕用 [new] 创建自己的实例），其状态由两个私有信号组成，并以只读方式公开。读取 [running()] 或 [error()] 的模板会在命令开始和结束时更新：这正是 [ChangeNotifier] 和 [ListenableBuilder] 在 [Flutter] 中所起的作用；
    • 第 26–38 行：执行一个操作：如果另一个操作正在进行，则什么也不做（第 27 行：防止按钮被按两次导致重复提交）；否则，将命令设为“进行中”；发生异常时，记录错误以便显示（第 33 行）；无论何种情况（[finally]，第 34–37 行），命令都不再处于进行中。错误的类型为 [unknown]：在 [JavaScript] 中，任何值都可以被抛出，因此 [TypeScript] 并不知道 [catch] 捕获到的是什么。

  title: string;

  private readonly http = inject(HttpClient);
  readonly captchaImage = captchaImage;

  readonly user = signal<User | null>(null); // null：无人登录
  readonly doctors = signal<Doctor[]>([]);
  readonly captcha = signal<Captcha | null>(null);
  readonly ready = signal(false); // 初始检查是否已完成？
  readonly serverError = signal<string | null>(null);
  readonly loginCommand = new Command();
  // 表单的字段，通过 [(ngModel)] 绑定
  readonly login = signal('admin');
  readonly password = signal('');
  readonly captchaAnswer = signal('');

  constructor() {
    this.checkSession();
  }

  private url(path: string): string {
    return `${config.serverUrl}/api${path}`;
  }

  // 一个 GET 请求，我们需要其 JSON 响应体。非
  // 2xx 的响应（或没有响应）会使 Promise 以 HttpErrorResponse 被拒绝
  private read<T>(path: string): Promise<T> {
    return firstValueFrom(this.http.get<T>(this.url(path)));
  }

  // 一个 POST：请求体对象会以 JSON 发送（content-type: application/json 头）
  private post<T>(path: string, body: object): Promise<T> {
    return firstValueFrom(this.http.post<T>(this.url(path), body));
  }

    this.captcha.set(await this.read<Captcha>('/captcha'));
    this.captchaAnswer.set('');
  }

    this.doctors.set(await this.read<Doctor[]>('/doctors'));
  }

  private async checkSession(): Promise<void> {
    try {
      this.user.set(await this.read<User>('/auth/me'));
      await this.loadDoctors();
    } catch (e) {
      // instanceof：类型测试；e.status：状态码（0：无响应）
      if (e instanceof HttpErrorResponse && e.status === 401) {
        await this.loadCaptcha();
      } else if (e instanceof HttpErrorResponse && e.status !== 0) {
        this.serverError.set(`The server responded ${e.status}.`);
      } else {
        this.serverError.set(`Is the RdvMedecins JSON server running (${config.serverUrl || 'port 8080'})?`);
      }
    }
    this.ready.set(true);
  }

    this.loginCommand.execute(() => this.logIn());
  }

  // 2. 登录

    try {
      const user = await this.post<User>('/auth/login', {
        login: this.login().trim(),
        password: this.password(),
        captchaId: this.captcha()?.id,
        captcha: this.captchaAnswer(),
      });
      this.password.set('');
      this.user.set(user);
      await this.loadDoctors();

      await this.loadCaptcha(); // 每张图片只使用一次

      throw new Error(`${e.status} - ${messages[key] ?? key}`);
    }
  }

    const error = this.loginCommand.error();

  // 4. 注销

    await this.post('/auth/logout', {});
    this.user.set(null);
    this.doctors.set([]);
    await this.loadCaptcha();
  }
}

// src/app/common/api-error.ts - 所有 API 错误共用的一个类
// -------------------------------------------------------------------------
// RdvMedecins 服务器的所有错误响应都具有相同的结构：
//   { "statusCode": 409, "key": "ERRORS.LOGIN_TAKEN", "params": {...}, "fields": {...} }
// 但是，请求也可能以其他方式失败：根本没有响应
// （网络中断、服务器已停止、地址错误），或者响应并非来自
// 我们的服务器（代理的错误页面）。Angular 的 HTTP
// 客户端把所有这些失败都报告为 HttpErrorResponse；我们
// 把它转换为同一个类 ApiError，它携带服务器
// 发送的翻译键（以及参数和每个字段的
// 错误，如果有的话）。
// =========================================================================

import { HttpErrorResponse } from '@angular/common/http';

// 一个对象 { name: text }
export type Texts = Record<string, string>;

// “extends Error”：一个完整的 JavaScript 错误，我们可以抛出
// （throw）和捕获（catch）它；message 为 "409 ERRORS.LOGIN_TAKEN"
export class ApiError extends Error {
  constructor(
    readonly statusCode: number, // 0：服务器没有响应
    readonly key: string, // 例如：'ERRORS.LOGIN_TAKEN'
    readonly params: Texts = {},
    readonly fields: Texts = {},
  ) {
    super(`${statusCode} ${key}`);
    this.name = 'ApiError';
  }

  // Angular HTTP 客户端的错误响应 -> 一个 ApiError
  static fromResponse(response: HttpErrorResponse): ApiError {
    // 状态码 0：无响应（网络中断、服务器已停止、地址错误）
    if (response.status === 0) {
      return new ApiError(0, 'ERRORS.SERVER_UNREACHABLE');
    }
    // error：响应的请求体，如果是 JSON 则已解码
    const body: unknown = response.error;
    if (isObject(body) && typeof body['key'] === 'string') {
      return new ApiError(response.status, body['key'], texts(body['params']), texts(body['fields']));
    }
    // 没有键：由代理或网络代替服务器作出了响应
    return new ApiError(
      response.status,
      response.status >= 500 ? 'ERRORS.SERVER_UNREACHABLE' : 'ERRORS.SERVER_ERROR',
    );
  }
}

// 一个“类型守卫”：如果函数返回 true，TypeScript 就知道
// value 是一个可以读取其属性的对象
function isObject(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

// 一个 JSON 对象 { "name": "ERRORS..." } -> Texts（否则为空）
function texts(json: unknown): Texts {
  if (!isObject(json)) return {};
  return Object.fromEntries(Object.entries(json).map(([key, value]) => [key, String(value)]));
}

    • 第 18 行：[Record<string, string>]：属性均为字符串的对象；
    • 第 22–31 行：[extends Error]：一个完整的 [JavaScript] 错误，可以被抛出（[throw]）和捕获（[catch]），并带有其调用栈。以 [readonly] 为前缀的构造函数参数会声明并初始化字段（这是 [TypeScript] 的简写形式）：状态码（0：无响应）、翻译键、其参数，以及每个字段的错误。错误消息（第 29 行）为“401 LOGIN.ERROR”，便于快速显示；

// src/app/common/api.ts - 向 API 发出请求，只需一行
// -------------------------------------------------------------------------
// 在示例 23 中，每个请求都重复了相同的步骤：服务器
// 地址、/api 前缀、把 Observable 转换为 Promise、读取
// 错误响应体……我们在这里把它们归并到一个服务中：
//
//   const doctors = await this.api.get<Person[]>('/doctors');
//   await this.api.post('/appointments', { day, slotId: 3 });
//
//   - 成功时，Promise 返回解码后的 JSON 请求体；
//   - 失败时，它以 ApiError 被拒绝。
// 所有请求都经过 request 方法：所有请求共有的问题
// 都应在此处处理（参见案例研究和
// 401 响应）。供示例 24 和 25 使用。

import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { inject, Injectable } from '@angular/core';
import { firstValueFrom } from 'rxjs';
import { config } from './config';
import { ApiError } from './api-error';

export type Method = 'GET' | 'POST' | 'PUT' | 'DELETE';

// providedIn: 'root'：整个应用程序只有一个实例
@Injectable({ providedIn: 'root' })
export class Api {
  private readonly http = inject(HttpClient);

  // <T>：期望的响应类型，由调用方选择
  async request<T>(method: Method, url: string, body?: unknown): Promise<T> {
    try {
      // http.request 返回一个 Observable；firstValueFrom 把它转换为
      // Promise（请求在此刻发送）。请求体对象会
      // 以 JSON 发送（content-type: application/json 头，服务器对
      // POST 要求有它）；JSON 响应会被解码（如果响应体为空则为 null）
      return await firstValueFrom(this.http.request<T>(method, `${config.serverUrl}/api${url}`, { body }));
    } catch (e) {
      // HTTP 客户端把任何失败（4xx、5xx、无响应）都报告为
      // HttpErrorResponse：我们对其进行转换。其余的（异常情况）原样通过
      throw e instanceof HttpErrorResponse ? ApiError.fromResponse(e) : e;
    }
  }

  get<T>(url: string): Promise<T> {
    return this.request<T>('GET', url);
  }

  // POST 总是带有 JSON 请求体：默认为 {}
  post<T>(url: string, body: unknown = {}): Promise<T> {
    return this.request<T>('POST', url, body);
  }

  put<T>(url: string, body: unknown): Promise<T> {
    return this.request<T>('PUT', url, body);
  }

  delete<T>(url: string, body?: unknown): Promise<T> {
    return this.request<T>('DELETE', url, body);
  }
}

    this.change(null);

  }

import { HttpParams } from '@angular/common/http';
import { inject, Injectable } from '@angular/core';
import { Api } from '../common/api';
import { Schedule, Person } from '../common/types';

@Injectable({ providedIn: 'root' })
export class RdvMedecins {
  private readonly api = inject(Api);

  getDoctors(): Promise<Person[]> {
    return this.api.get<Person[]>('/doctors');
  }

  getClients(): Promise<Person[]> {
    return this.api.get<Person[]>('/clients');
  }

  // HttpParams 构造出 "doctorId=1&day=2030-01-15"，并对需要的内容进行编码
  getSchedule(doctorId: number, day: string): Promise<Schedule> {
    const params = new HttpParams().set('doctorId', doctorId).set('day', day);
    return this.api.get<Schedule>(`/schedule?${params.toString()}`);
  }

  // clientId?：可选参数。...(condition && object)：
  // 只有在提供了 clientId 时，才会把 clientId 属性放入请求体
  async book(day: string, slotId: number, clientId?: number | null): Promise<void> {
    await this.api.post('/appointments', { day, slotId, ...(clientId != null && { clientId }) });
  }

  async cancelAppointment(appointmentId: number): Promise<void> {
    await this.api.delete(`/appointments/${appointmentId}`);
  }
}

import { computed, inject, Injectable, signal } from '@angular/core';
import { ApiError } from '../common/api-error';
import { Schedule, ScheduleSlot, timeRange, Person, User } from '../common/types';
import { RdvMedecins } from './rdvmedecins';

// 一个日期 -> "2026-10-07"（本地日期；toISOString 会给出格林尼治的日期）
export function formatDay(d: Date): string {
  const twoDigits = (n: number) => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${twoDigits(d.getMonth() + 1)}-${twoDigits(d.getDate())}`;
}

// 明天：今天的日期加一天
function tomorrow(): Date {
  const d = new Date();
  d.setDate(d.getDate() + 1);
  return d;
}

export interface Message {
  success: boolean;
  text: string;
}

@Injectable()
export class ScheduleModel {
  private readonly rdvmedecins = inject(RdvMedecins);

  // —— 状态 ——
  readonly user = signal<User | null>(null);
  readonly doctors = signal<Person[]>([]);
  readonly clients = signal<Person[]>([]);
  readonly doctorId = signal<number | null>(null);
  readonly day = signal(formatDay(tomorrow()));
  readonly clientId = signal<number | null>(null);
  readonly schedule = signal<Schedule | null>(null);
  readonly loading = signal(false);
  readonly message = signal<Message | null>(null);

  private readonly cache = new Map<string, Schedule>();
  private readNumber = 0;

  // —— 计算值 ——
  readonly loggedIn = computed(() => this.user() !== null);
  readonly isManager = computed(() => this.loggedIn() && this.user()?.role !== 'USER');

  // —— 各个操作 ——
  async changeUser(u: User | null): Promise<void> {
    this.user.set(u);
    this.doctors.set([]);
    this.clients.set([]);
    this.schedule.set(null);
    this.doctorId.set(null);
    this.message.set(null);
    this.cache.clear(); // 权限已变化：我们忘记一切
    if (u === null) return;
    this.doctors.set(await this.rdvmedecins.getDoctors());
    // USER 会收到 403
    if (this.isManager()) this.clients.set(await this.rdvmedecins.getClients());
  }

  chooseDoctor(id: number): void {
    this.doctorId.set(id);
    this.message.set(null);
    this.readSchedule();
  }

  chooseDay(day: string): void {
    this.day.set(day);
    this.message.set(null);
    this.readSchedule();
  }

  chooseClient(id: number | null): void {
    this.clientId.set(id);
  }

  book(c: ScheduleSlot): Promise<void> {
    return this.act(
      () => this.rdvmedecins.book(this.day(), c.id, this.isManager() ? this.clientId() : null),
      `Slot ${timeRange(c)} booked.`,
    );
  }

  cancel(c: ScheduleSlot): Promise<void> {
    return this.act(() => this.rdvmedecins.cancelAppointment(c.appointmentId!), `Appointment of ${timeRange(c)} cancelled.`);
  }

  // 一个操作，然后总是重新读取日程：以服务器为准
  private async act(action: () => Promise<void>, success: string): Promise<void> {
    try {
      await action();
      this.message.set({ success: true, text: success });
    } catch (e) {
      this.message.set({ success: false, text: e instanceof ApiError ? e.message : String(e) });
    }
    await this.readSchedule();
  }

  private async readSchedule(): Promise<void> {
    const id = this.doctorId();
    if (id === null) return;
    const key = `${id}/${this.day()}`;
    const number = ++this.readNumber;
    // 先读缓存（或什么都没有），然后读取
    this.schedule.set(this.cache.get(key) ?? null);
    this.loading.set(true);
    try {
      const read = await this.rdvmedecins.getSchedule(id, this.day());
      if (number !== this.readNumber) return; // 已启动了一次更新的读取
      this.cache.set(key, read);
      this.schedule.set(read);
    } catch (e) {
      if (number !== this.readNumber) return;
      this.schedule.set(null);
      this.message.set({ success: false, text: e instanceof ApiError ? e.message : String(e) });
    }
    this.loading.set(false);
  }
}

// src/app/ex25-server-errors/ex25.page.ts - 显示服务器的错误

// 客户管理（管理员账户）。这个表单有意
// 在手机上不做任何验证：所有内容都发送到
// 服务器，若被拒绝，服务器会返回一个 JSON 错误（由 common/api.ts 转换为
// ApiError）：
//
//   400 { key: 'ERRORS.INVALID_FORM', fields: { lastName: 'ERRORS.LASTNAME_REQUIRED' } }
//   409 { key: 'ERRORS.PATIENT_ALREADY_EXISTS', fields: { firstName: ..., lastName: ... } }
//   409 { key: 'ERRORS.CONCURRENT_UPDATE' }         （乐观锁）
//
// 每个字段的错误（ApiError.fields）会交给其表单
// 控件（setErrors）：ion-input 在字段下方显示它（errorText）。
// 其消息是服务器发送的键，由屏幕进行翻译
// （示例 21 的字典）。修改字段会清除其错误。
// 试试：空姓名、称谓“Dr”、同名者（Alice DURAND）、
// 已被占用的登录名（martin）、在两台设备上修改同一条记录……
// =========================================================================

import { Component, inject, signal } from '@angular/core';
import { NonNullableFormBuilder, ReactiveFormsModule } from '@angular/forms';
import {
  IonBackButton, IonButton, IonButtons, IonCard, IonCardContent, IonCardHeader, IonCardTitle, IonContent, IonHeader,
  IonIcon, IonInput, IonItem, IonLabel, IonList, IonNote, IonPopover, IonSelect, IonSelectOption, IonText, IonTitle,
  IonToolbar,
} from '@ionic/angular';
import { addIcons } from 'ionicons';
import { createOutline, languageOutline, trashOutline } from 'ionicons/icons';
import { Api } from '../common/api';
import { LoginBar } from '../common/login-bar';
import { ApiError, Texts } from '../common/api-error';
import { fullName, Person, User } from '../common/types';
import { injectConfirmation } from '../ex16-confirmation/confirmation';
import { languages, Translations } from '../ex21-i18n/translations';
import { Command } from '../ex23-login/command';

// 表单的字段，以及要翻译的消息（一个键及其参数）
type Field = 'title' | 'firstName' | 'lastName' | 'login' | 'password';
interface Success {
  key: string;
  params: Texts;
}

@Component({
  selector: 'app-ex25',
  imports: [
    ReactiveFormsModule, IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle, IonButton, IonIcon, IonPopover,
    IonContent, IonList, IonItem, IonLabel, IonCard, IonCardHeader, IonCardTitle, IonCardContent, IonSelect,
    IonSelectOption, IonInput, IonText, IonNote, LoginBar,
  ],
  templateUrl: './ex25.page.html',
  // 页面的翻译，使用字典 ex25-fr.json 和 ex25-en.json
  providers: [{ provide: Translations, useFactory: () => new Translations('ex25') }],
  styles: `
    .warning { --background: #fff8e1; --color: #333; }
    .message { margin-top: 12px; }
    .status { font-size: 12px; }
  `,
})
export class Ex25Page {
  private readonly api = inject(Api);
  private readonly confirm = injectConfirmation();
  readonly tr = inject(Translations);
  readonly languages = languages;
  readonly titles = ['Mr', 'Mme', 'Melle', 'Dr']; // "Dr"：服务器会拒绝它
  readonly fullName = fullName;

  readonly user = signal<User | null>(null);
  readonly clients = signal<Person[]>([]);

  // 表单：没有任何验证规则，一切由服务器检查
  readonly form = inject(NonNullableFormBuilder).group({
    title: ['Mr'],
    firstName: [''],
    lastName: [''],
    login: [''],
    password: [''],
  });
  // null：新建；否则为被修改客户的 id，以及随其记录一起读取的版本
  readonly editedId = signal<number | null>(null);
  private version = 0;

  // 最近一次错误的通用消息，以及成功消息
  readonly pageError = signal<ApiError | null>(null);
  readonly success = signal<Success | null>(null);
  // 向服务器发送：一个 Command（示例 23），它会告知是否正在运行
  readonly sending = new Command();

  constructor() {
    addIcons({ languageOutline, createOutline, trashOutline });
    this.tr.start();
  }

  isAdmin(): boolean {
    return this.user()?.role === 'ADMIN';
  }

  private async reload(): Promise<void> {
    this.clients.set(await this.api.get<Person[]>('/clients'));
  }

  async onUserChange(u: User | null): Promise<void> {
    this.user.set(u);
    this.clients.set([]);
    if (u?.role === 'ADMIN') await this.reload();
  }

  // 服务器返回的字段错误，已翻译（''：无错误）
  fieldError(field: Field): string {
    const key = this.form.controls[field].errors?.['server'];
    return typeof key === 'string' ? this.tr.t(key) : '';
  }

  private clearMessages(): void {
    this.pageError.set(null);
    this.success.set(null);
  }

  newForm(): void {
    this.editedId.set(null);
    this.version = 0;
    // 重置：起始值，并且不再有错误
    this.form.reset();
    this.clearMessages();
  }

  edit(c: Person): void {
    this.editedId.set(c.id);
    // 随记录读取的版本会随修改一并发回：如果有人
    // 在此期间修改了该记录，服务器会返回 409 CONCURRENT_UPDATE
    this.version = c.version;
    this.form.reset({ title: c.title, firstName: c.firstName, lastName: c.lastName, login: c.login ?? '', password: '' });
    this.clearMessages();
  }

  // “保存”按钮
  submit(): void {
    this.sending.execute(() => this.save());
  }

  private async save(): Promise<void> {
    this.clearMessages();
    const input = { ...this.form.getRawValue(), version: this.version };
    const id = this.editedId();
    try {
      const client =
        id === null
          ? await this.api.post<Person>('/clients', input)
          : await this.api.put<Person>(`/clients/${id}`, input);
      this.newForm(); // 表单已清空，消息已清除……
      // ……除了这一条
      this.success.set({
        key: id === null ? 'FORM.ADDED' : 'FORM.UPDATED',
        params: { name: `${client.firstName} ${client.lastName}`, login: client.login ?? '' },
      });
      await this.reload();
    } catch (e) {
      if (!(e instanceof ApiError)) throw e;
      this.pageError.set(e); // 通用消息
      // 每个字段的错误：交给其控件，该控件
      // 随之变为无效（ng-invalid）；markAsTouched 把它标记为“已接触”
      // （ng-touched）：Ionic 随后会显示其 errorText
      for (const [field, key] of Object.entries(e.fields)) {
        const control = this.form.get(field);
        control?.setErrors({ server: key });
        control?.markAsTouched();
      }
    }
  }

  async remove(c: Person): Promise<void> {
    const name = `${c.firstName} ${c.lastName}`;
    if (!(await this.confirm(this.tr.t('FORM.DELETE_CONFIRM', { name })))) return;
    this.clearMessages();
    try {
      await this.api.delete(`/clients/${c.id}`);
      this.success.set({ key: 'FORM.DELETED', params: { name } });
    } catch (e) {
      if (e instanceof ApiError) this.pageError.set(e);
    }
    await this.reload();
  }
}
