    13. 结论

    我们已经开发出了 [Ionic] 的 [RdvMedecins] 应用客户端。对用户而言，它提供与 [NestJS] 课程中的 HTML 应用程序、与 [Vue.js]、[Angular] 和 [React] 课程中的客户端，以及之前课程中的 [Flutter] 客户端相同的屏幕；它是安装在手机上的移动应用，同时无需任何修改，它也是一个 Web 应用。

    而服务器则没有变化。它的 API 和 JSON——其契约（路由、请求体、状态码和错误键）足以让人在从不阅读其代码的情况下编写客户端——可同时为浏览器和手机提供服务，两者可以互换。在手机上，没有浏览器来保存令牌 Cookie：这由 [Android] 的原生代码通过 [CapacitorHttp] 插件承担，应用程序中无需写一行代码（相比之下，[Flutter] 客户端必须借助其 [CookieClient] 类来做到这一点）。安全性保持不变：仍然是服务器对用户进行身份验证、检查角色和管理规则，并决定患者被授权查看什么。

    学过 [Flutter] 课程的读者可以对两者进行比较：

    • 两者基于同一个理念：界面是状态的函数。[Flutter] 控件有一个返回控件树的 [build()] 方法；[Angular] 组件有一个读取信号的模板。当状态发生变化时（[setState] / 信号），屏幕随之更新。有了信号，[Angular] 甚至确切地知道模板的哪些部分依赖于哪个信号：它无需进行比较；
    • [Flutter] 用它自己的引擎绘制每个像素；[Ionic] 生成 HTML，由手机的 WebView（[Chrome] 引擎）渲染。这带来了一个轻量而直观的 Web 应用（它是一个普通网页）、属于标准 Web 工具的开发工具（[Chrome] 开发者工具，在电脑和手机上都可用），以及可复用的专业知识（HTML、CSS、[TypeScript]、[Angular]）。代价是：应用依赖于手机的 WebView，动画很多或负载很重的界面在那里运行得不如使用 [Flutter] 引擎时流畅；
    • [Ionic] 的组件以两种模式模仿原生组件：[md] （[Android]）和 [ios]（[iPhone]）：同一个应用会呈现出每个系统的外观和手感。[Flutter] 同样提供这两个控件系列（[Material] 和 [Cupertino]），但由开发者自己选择；
    • [Angular] 提供的内容远多于 [React]，与 [Flutter] 大致相当：路由器、表单、HTTP 客户端、依赖注入、格式化；[Ionic] 增加了移动端组件和栈式导航；[Capacitor] 增加了对手机的访问能力。该客户端不需要任何其他库。另一方面，布局由 CSS 处理（[Ionic] 的网格和工具类），而 [Flutter] 使用控件（[Column]、[Row]、[Padding]……）；
    • [TypeScript] 的严格模式以及严格的模板验证（[strictTemplates]）能检测出 [Dart] 在编译时检测的大部分错误：缺失的 [null] 值、拼错的属性，或类型错误的参数。然而，[TypeScript] 的类型在运行时会消失：格式错误的 JSON 在接收时不会被检测到，而 [Dart] 3 的过滤则可以做到；
    • 作为回报：每个组件有两个文件（类和模板）、一个要填写的装饰器（[imports]、[templateUrl]），以及在 [Angular]、[Ionic] 和 [Capacitor] 之间的三个工具——你需要理解它们各自的作用。

    本课程所涵盖的 [Ionic] 和 [Angular] 概念（组件、信号、模板、输入和输出、生命周期、依赖注入、指令、路由器和守卫、响应式表单、[Promise] 和 [Observable]、国际化，以及 [Capacitor] 插件）是所有 [Ionic] 应用所共有的。延伸阅读：

    • 官方文档：ionicframework.com/docs（组件列表，附带其属性和示例）、angular.dev（其教程和指南），以及 capacitorjs.com/docs；
    • 测试：[Angular] 的单元测试（[ng test]，配合 [Vitest]），它们无需真实的浏览器即可与组件交互，以及端到端测试（[Playwright]，用于生成本文档中的截图），它们在浏览器中运行真实的应用程序；
    • 状态管理库（[NgRx] 及其对应的 [SignalStore]），在共享状态变得非常复杂时很有用；
    • [Capacitor] 插件：令牌的安全存储、通知、相机、地理定位、分享等等——每种需求一个插件，无论是官方的还是社区开发的；
    • 渐进式 Web 应用（PWA）：应用的 Web 版本，可安装并可离线使用，借助 [@angular/pwa] 包实现；
    • iPhone：同一份代码可以生成 [iOS] 应用 （[npx cap add ios]），需要在 [Mac] 上使用 [Xcode] 构建；[Ionic] 的组件会自动呈现 [iOS] 的外观，除非强制使用 [md] 模式。
